# Керування планувальником алгоритмів

## Огляд

Адміністративна панель тепер включає повноцінне керування планувальником алгоритмів через вкладку **"Планувальник"**.

## Можливості

### 1. Перегляд статусу планувальника

- Статус роботи планувальника (🟢 Активний / 🔴 Зупинений)
- Загальна кількість алгоритмів у системі
- Список всіх алгоритмів з деталями

### 2. Інформація про кожен алгоритм

- **Назва**: Системна назва та відображувана назва
- **Інтервал**: Як часто виконується (кожні N хвилин/годин/днів)
- **Статус**:
  - ⏸️ Очікує (idle)
  - 🔄 Виконується (running)
  - ❌ Помилка (error)
- **Останній запуск**: Час останнього виконання
- **Увімкнено/Вимкнено**: Візуальний індикатор (зелена/сіра точка)

### 3. Керування алгоритмами

#### Увімкнути/Вимкнути алгоритм

- Кнопка **"Увімкнути"** або **"Вимкнути"**
- Змінює статус алгоритму для всіх користувачів
- Вимкнені алгоритми не виконуються за розкладом
- Підтвердження через діалог

#### Запустити вручну

- Кнопка **"▶️ Запустити"**
- Негайно виконує алгоритм для всіх користувачів
- Доступна тільки для увімкнених алгоритмів
- Корисно для тестування та екстреного запуску
- Підтвердження через діалог

## Технічні деталі

### Структура компонентів

```
src/components/admin/SchedulerTab.tsx - UI компонент
src/server/api/routers/admin.ts - Backend endpoints (getSchedulerStatus, toggleAlgorithm, runAlgorithmManually)
src/server/scheduler.ts - Scheduler з новими методами
src/server/taskrunner.ts - TaskRunner з полями isEnabled, lastRun, status
```

### Backend endpoints (tRPC)

#### `admin.getSchedulerStatus`

Повертає:

```typescript
{
  isRunning: boolean,
  algorithms: [
    {
      name: string,
      displayName: string,
      interval: string,
      enabled: boolean,
      lastRun?: Date,
      status: "idle" | "running" | "error"
    }
  ]
}
```

#### `admin.toggleAlgorithm`

Вхід:

```typescript
{
  algorithmName: string,
  enabled: boolean
}
```

#### `admin.runAlgorithmManually`

Вхід:

```typescript
{
  algorithmName: string;
}
```

### Додані методи до Scheduler

- `getAlgorithmsInfo()` - Повертає інформацію про всі алгоритми
- `toggleAlgorithm(name, enabled)` - Увімкнути/вимкнути алгоритм
- `runAlgorithmManually(name)` - Запустити алгоритм вручну
- `getDisplayName(name)` - Конвертує системну назву в людський вигляд
- `getIntervalDisplay(cron)` - Конвертує cron вираз в людський вигляд

### Додані поля до TaskRunner

- `isEnabled: boolean` - Чи увімкнено алгоритм (за замовчуванням `true`)
- `lastRun?: Date` - Час останнього запуску
- `status: "idle" | "running" | "error"` - Поточний статус виконання
- `setEnabled(enabled)` - Встановити статус увімкнено/вимкнено

### Логіка executeAll()

TaskRunner тепер:

1. Перевіряє `isEnabled` перед виконанням
2. Встановлює `status = "running"` на початку
3. Зберігає `lastRun = new Date()`
4. Встановлює `status = "idle"` при успіху або `status = "error"` при помилці

## Логування алгоритмів

### Автоматичне логування в БД

- Всі логи алгоритмів (`logger.debug/info/warn/error`) зберігаються в таблицю `algorithm_logs`
- Контекст встановлюється автоматично через `setAlgorithmContext()` перед кожним запуском
- Логи включають: `algorithm`, `level`, `message`, `userId`, `executionId`, `createdAt`

### Автоматична очистка

- Логи старші за 5 днів автоматично видаляються при кожному записі
- Очистка відбувається в фоні, не блокує виконання

### Перегляд логів

Використовуйте вкладку **"Алгоритми"** для:

- Фільтрації по алгоритму, рівню, користувачу, даті
- Пагінації (50 логів на сторінку)
- Сортування по часу створення (найновіші зверху)

## Використання

1. Відкрийте `/admin` (потрібні права адміністратора)
2. Перейдіть на вкладку **"Планувальник"**
3. Переглядайте статус всіх алгоритмів
4. Використовуйте кнопки для керування:
   - **Вимкнути** - зупинити автоматичне виконання
   - **Увімкнути** - відновити автоматичне виконання
   - **▶️ Запустити** - виконати негайно для тестування

## Безпека

- Всі endpoints захищені `adminProcedure` middleware
- Перевіряється `isAdmin = true` та `isBlocked = false`
- Підтвердження через `confirm()` діалог перед кожною дією
- Блокування UI під час виконання операцій (`disabled` стан)
